# Goal
Rewrite the portal's cell isolation so a newly committed or role-changed cell no longer costs a walk of its whole subtree with one command per node: the cell's role is stamped when it spawns, and Bevy's own hierarchy propagation carries the render layers down (track: Portal; the 160 fps goal; approved 2026-10-07 by Upstream Dev for the user).

# Context
- Design to implement: Design 1 of `local/agents/runs/research-646-isolate-cells-design.1/report.md` (read it all first, then "Recommendation + steps" items 2, 3, 5). Measurement it must improve: spans `portal/isolate`, counters `portal/cells_relayered` / `portal/nodes_relayered` (already in portal.rs, added by impl-644).
- Today: `isolate_cells` (crates/engine/src/portal.rs, search `fn isolate_cells`) classifies every cell root (`CellRole`: Active / Destination / Hidden) and, for a root that is new or changed role, walks `children.iter_descendants(root)` calling `relayer_node` per node; plus three repair passes (`Changed<Children>`, `Changed<RenderLayers>`/`RemovedComponents<RenderLayers>`, door-layer natives) and `PortalOriginalLayers` to restore a node's own layers.
- Bevy 0.19 propagation: `HierarchyPropagatePlugin::<RenderLayers>` (bevy_app-0.19.0/src/propagate.rs; `Propagate<C>`, `PropagateOver<C>`, `PropagateStop<C>`, `Inherited<C>`, `PropagateSet<C>`), already added by `crate::render::add_placed_object_layer_propagation` (render.rs ~311-330), scheduled in PostUpdate before `VisibilitySystems::CheckVisibility`.
- **The gap the design missed (must be solved explicitly):** every placed reference is ALREADY its own propagation source: streaming.rs inserts `Propagate(PLACED_OBJECT_RENDER_LAYERS)` on each reference entity (search `Propagate(PLACED_OBJECT_RENDER_LAYERS)`), so the reference's meshes are on the placed-object layer (the water reflection camera leaves them out). A `Propagate` source on the cell root would STOP at each reference (a nested source wins), so Destination/Hidden would never reach reference meshes. Required solution: the reference's source carries ONE combined value = f(cell role, placed-object layer): Active -> PLACED_OBJECT_RENDER_LAYERS (today's value), Destination -> the portal layer (2) [check what today's `layers_for`/`wanted_for` give a reference mesh in a destination cell and reproduce it exactly], Hidden -> `RenderLayers::none()`. So a role change writes: the root's source + each reference source in that cell (O(references), not O(nodes)) - or choose a layered component if you find a cleaner Bevy-native way; explain the choice. Terrain/water/other non-reference children follow the root's source. Water planes keep their own layer as own sources as the design says.
- Lights: `crate::render::light_render_layers()` returns `(RenderLayers, PropagateOver<RenderLayers>)` for lights - read it; keep lights' behaviour (lights.rs `budget_lights` splits by layer).
- Contracts to keep (tests pin them): impl-191 one-frame rule (a node's layers move in one frame), door-layer natives hidden, shadows of destination cells via the portal sun (shadow_layers.rs), water through a doorway, `PortalHiddenCell` + `Visibility::Hidden` on Hidden roots.
