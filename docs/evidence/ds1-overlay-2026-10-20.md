## Contract and decisions

- The base remains immutable during derivation. Cluster tables live in `clusters.db`,
  payloads and extension receipts in the overlay. Runtime SQL opens the base read-only
  and attaches the bound overlay read-only. Core authority uses base tables.
- Settings identity is centralized in `derive_extensions::resolved_settings`: threshold,
  terrain, tree inclusion, converter version and builder identity; jobs and label do not affect it.
  D9/P2 can extend this seam without inventing a second identity function.
  The exact object is recorded as `build_settings`; readers recompute and validate its id.
- Per the lead's decision, full `cluster` and `auto` conversions publish a clusterless
  base and invoke the same derive writer. Failed automatic capability probes remain
  recorded; offline cluster derivation still runs. A derive failure leaves a valid base
  and returns its cause with an exact command preserving the conversion's settings.
- The review-round-1 ruling supersedes the original blanket `derived/` guard: bookkeeping
  alone does not require discard. Real overlays and live staging remain protected. Discard
  is deferred until successful publication; failed reconversion preserves the old overlays.
- Labels are unique within a base. `--replace` replaces the overlay with that label across
  settings IDs. Distinct retained variants need distinct labels.
- Recorded base asset failures are admitted as explicit retained core limitations and
  recorded as `base_failure_count`; the engine's incomplete-assets gate remains authoritative.
- Full-conversion `--cluster-bench-baked` is refused: the standalone
  `cluster-stage --converted <base> --work <new-work> --bench-baked` remains the
  measurement path. It cannot be a second full-conversion cluster writer.
- Review M1: move raw terrain inputs into an owned sibling `.terrain-sources-*`
  directory, retaining only those inputs for a failed derive retry.
  A `.base-published` marker also prevents resume if detachment or cleanup fails.
- Review round 2 supersedes the provisional admission factors: measured object/table/terrain
  ratios provide only a fast-fail hint, or a prior same-base overlay supplies its actual size.
  The shared write-time guard is authoritative for the unchanged 10 GiB retained floor.

## Review limits and deferred findings

The initial implementation review and the later independent Claude review use separate
finding numbers. The latter returned no Critical or High findings and requested the fixes below.

- Repeated binding checks are no longer deferred: the shadow reader's `world()` opens a
  connection per world. The envelope now retains one launch receipt; certification, package,
  terrain and shadow connections reuse it. Each connection executes one `main.lod_build`
  identity query before read-only ATTACH. Full-check calls and total milliseconds are
  counted in-process and logged once when the launch receipt is established.
- M5: resolved settings, version and builder identity are now recorded. Binding errors
  reconstruct the full threshold/terrain/tree/label command, with PowerShell quoting.
  Terrain host provenance is recorded outside the settings hash. Reproducing an old
  builder's variant requires its recorded converter version, not arbitrary newer code.
- Remaining design gap: a successful full terrain conversion removes its temporary raw
  VFS. Its receipt can record that input root but cannot retain its bytes. The rebuild
  hint explains that matching raw DDS inputs must be restored or supplied elsewhere.
- L1: converter preflight rejects a base manifest claiming `derived/`. A separate
  engine guard against a hand-authored base/overlay pair making that claim is deferred.
- The sidecar error's run of spaces is fixed. Timestamp convention and the minor terrain
  schema comment remain cosmetic limitations; no validation behavior depends on them.
- L3: invalidate the old terrain manifest on conversion resume, alongside other
  generated cluster outputs.
- L4: concurrent first derives may race creating `derived/`, or fail acquiring a
  sibling hint lock. They fail without publishing mixed data; retry is required.
- L5: post-publish derive retains full base preflight hashing, as required by the
  single derive path. No trusted-publisher bypass was added.
- L7: writer-to-reader lock handoff has a fail-safe gap; repair ownership still guards
  base publication. A competing writer can make the overlay step fail for retry.
