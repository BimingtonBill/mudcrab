# PR 3 implementation brief — engine: the distant-LOD terrain tier

## Goal

With `--lod`, the engine streams Skyrim's precomputed **terrain** LOD blocks (`lod_block` rows, `meshes/terrain/**/*.glb`) as ordinary scene entities in nested distance bands around the camera, following the floating origin, with hysteresis unload, a shared frame commit budget, counters and an invariant validator. No renderer or WGSL change. LOD stays **off by default** until PR 5. Object blocks and tree billboards are PR 4; the types here already carry `kind` so PR 4 adds no plumbing.

## Design decisions

Each decision names the reason it is the right one. Where the design doc left a choice open, the choice made here is marked **[new]** and is the thing to argue with.

1. **Band selection is a pure function of `(camera_cell, bands, available_keys, resident_keys, stream_radius, unload_scale)`.** The camera cell is derived exactly as `plan_cells` derives it (`streaming.rs:278-283`: `translation + origin * CELL_SIZE`, `-translation.z` for y). Reason: a pure core is the only part that is testable with no game data and no `App`, and cell-granular input makes selection stable while the camera moves inside a cell.
2. **Block coordinate for cell `(cx, cy)` at level `L` is `(cx.div_euclid(L) * L, cy.div_euclid(L) * L)`**, `L` clamped to ≥ 1. Reason: `div_euclid` is what puts negative cells in the negative block, which is what the shipped file names do (`tamriel.4.-12.-12.btr`); `i32::div_euclid` is one call.
3. **Distance is measured from the camera cell's 1×1 rectangle to the block's `L×L` cell rectangle, in Creation units, 0 when they overlap.** Reason: rect-to-rect is conservative (a block containing the camera is always in band), stable in cell steps, and is the same quantity for every level.
4. **A block is selected only if it is not fully covered by the full-detail rectangle** (`plan_cells`' *planned* `stream_radius` square around the camera cell, not the set of cells that actually committed). Reason: planned is a pure function of the camera cell (decision 1); using the resident set would pop LOD blocks in and out on every cell commit/unload, and any hole a failed cell leaves is still covered by the coarser level underneath (decision 5).
5. **Coarser levels are never skipped because a finer level covers them.** Levels stay nested and resident; the fully-covered rule (decision 4) only ever compares against the full-detail rectangle. Reason: the horizon stays populated while a finer block loads or after one fails, and it bounds a missing block's visual cost to one LOD step — the design's "zero loading screens at the LOD scale".
6. **Hysteresis: a block is requested when `distance <= band.distance`, and kept while `distance <= band.distance * lod_unload_scale` (default 1.1).** A resident block outside its relaxed band is unloaded in the same frame it falls out; a block that becomes fully covered is unloaded by the same rule (it is simply absent from the desired set). Reason: one rule covers band exit and coverage change, and mirrors the stream/unload radius pair the engine already has.
7. **Bands are a `Vec<LodBand { level: u8, distance: f32 }>` sorted by level, all levels of one `kind`.** Default (Medium preset, measured): `4:20000, 8:32000, 16:100000`. `--lod-distances high` → `4:35000, 8:70000, 16:250000`; `ultra` → `4:60000, 8:90000, 16:250000`; an explicit `4:20000,8:32000,16:100000,32:250000` list is also accepted. Level 32 is deliberately not in any preset (under nested residency a level-32 band inside level-16's reach adds nothing); it stays available via the explicit list for the horizon-only experiment of design §6 open question 6. Reason: the presets are the shipped INI numbers, and the fine/coarse nesting question stays a measurement, not a default.
8. **Placement: `block_translation = ((block_x - origin.x) * CELL_SIZE, -depth_offset_for(level), -(block_y - origin.y) * CELL_SIZE)`**, i.e. the block's south-west cell placed exactly like a cell root (`streaming.rs:1402`) with the depth lowering on `Y`. Reason: the converted block meshes are block-local with the SW corner at the origin and already run through `CREATION_TO_RUNTIME_ROTATION`, so the root transform is the same one a cell uses; and the lowering is a config value, not a mesh edit or a shader.
9. **[new] The depth lowering steps per level: `depth_offset_for(level) = lod_depth_offset * (index_of_level_in_bands + 1)`,** default `lod_depth_offset = 32` units, so level 4 sits 32 units, level 8 64, level 16 96 below true height. Reason: with nested residency two LOD levels cover the same ground; a single constant leaves them coplanar and z-fighting, while an increasing offset keeps the *finest resident* surface always in front and everything below full-detail terrain, which is exactly the ordering design §6.4(a) wants. The step is 0.45 m at level 4 — sub-pixel at the 20 000-unit band.
10. **Rebasing: widen `update_render_origin`'s query to `Or<(With<ExteriorCellGrid>, With<LodBlockRoot>)>` and preserve `translation.y` when rewriting.** Reason: the existing assignment (`streaming.rs:1844-1850`) writes `y = 0.0` unconditionally, which would silently erase the LOD lowering. One `let y = transform.translation.y` before the write; a test pins it (decision 8's offset must survive every rebase).
11. **The block table is read once at startup through a dedicated read-only connection, following `AssetCatalog::open` (`database.rs:89`); per-block payloads go through the existing worker.** The table (`LodBlockTable { keys: HashSet<LodBlockKey> }`, `SELECT kind,level,block_x,block_y FROM lod_block WHERE worldspace_id=?1`) is the planner's *availability* input — reason: the planner must never request a block the worldspace does not have, and this keeps the per-frame plan free of SQL. The payload (`DatabaseRequest::LoadLod` → `LodBlockPayload { key, mesh_path, bounds_min, bounds_max }`, design §6.3) keeps row reads off the main thread and is the seam PR 4 extends with tree instances. **Note for the reviewer:** for terrain the payload duplicates the table row, so if you prefer, step 3 can answer from the table and the worker request lands with PR 4's instances; the plugin's call site is the only thing that changes.
12. **Same worker, two response channels.** `DatabaseRequest` gains `LoadLod { generation, key, queued_at }`; the worker gains a `Sender<LodResponse>` and `WorldDatabase` a second `Receiver` with `try_lod_response()`. Reason: one read-only `Connection` cannot be shared across threads, and a second thread would need its own connection and its own queue for no gain (~60 blocks resident at Medium). **Trap:** `worker()` matches with `let DatabaseRequest::Load { .. } = request else { break }` (`database.rs:215-221`) — adding a variant without restructuring that match **kills the worker silently on the first LOD request**. Restructure to an exhaustive `match` (the `Shutdown` arm is the only break).
13. **Request pressure is bounded:** `lod_requests_per_frame` (default 4) new requests per frame and at most `lod_max_in_flight` (default 8) blocks in `Loading`. Reason: the request channel is `bounded(128)` and `request()` blocks the main thread when full (`database.rs:145`, `:165`), so an unbounded burst on a teleport is a stall.
14. **Residency states mirror the streamer:** `LodBlockStatus::{Loading{generation}, Resident{root}, Failed}`, keyed by `LodBlockKey { worldspace_id, kind, level, block_x, block_y }`; generation is bumped per request and a response whose key is not `Loading` or whose generation differs is counted stale and dropped. Reason: the same discipline already proven for cells, including the teleport case the streaming fixture exercises.
15. **A `Failed` block stays in the map and is not retried while it stays inside its band;** it unloads with the band like any other. Reason: mirrors `CellStatus::Failed`, and prevents a missing `.glb` from being re-requested every frame and inflating `lod_asset_failures`.
16. **Commit budget: share the *time* budget and the frame window; keep the per-frame *counts* separate.** New resource `#[derive(Resource)] pub struct CommitBudget { started: Instant, commits: usize }`; a `begin_commit_budget` system at the head of the `Update` chain sets `started = Instant::now()`; `collect_cells` replaces its local `frame_commit_started`/`commits_this_frame` with it; `collect_lod_blocks` loops while it has commits left **and** `budget.started.elapsed() < config.max_commit_micros_per_frame`. The tail accounting of `collect_cells` (`streaming.rs:468-489`) moves to a `finish_commit_budget` system at the end of the LOD chain, so `commit_frames`/`max_frame_commit_micros`/`commit_budget_violations` cover both tiers. Reason: the shipped `max_cell_commits_per_frame` is **1**; a single shared *count* would let full-detail cells starve the LOD tier permanently while flying — precisely when the horizon matters — whereas the micros budget is what actually protects `commit_budget_respected` and the P95 gate. Each tier keeps its own count (`config.max_cell_commits_per_frame`, new `config.lod_commits_per_frame`, default 4).
17. **Ordering: a public `SystemSet`.** `#[derive(SystemSet, Debug, Clone, PartialEq, Eq, Hash)] pub struct StreamingSet;` in `streaming.rs`, the existing chain `.chain().in_set(StreamingSet)`, and `LodPlugin`'s chain `.after(StreamingSet)`. Reason: the module boundary means `lod.rs` cannot name `plan_cells`, and cells must get first claim on the budget; a set is the smallest ordering primitive that survives the split (the crate has none today).
18. **Materials come from the GLB; the engine only aligns them.** Each block loads `GltfAssetLabel::Scene(0)` with `WorldAssetRoot` exactly as references do (`streaming.rs:647-662`), so the converter's material — diffuse + `_n` normal for `.btr` — and its texture URIs are authoritative and the engine never re-derives the `opensky-srgb` naming. When the scene is ready, walk its `MeshMaterial3d<StandardMaterial>` handles once and set `cull_mode: None, double_sided: true, perceptual_roughness: 0.92` (design §6.3's terrain material); this is a per-block GLB material, so the rewrite cannot leak into shared materials. Reason: the alternative (engine-built material from paths) would need texture-path conventions the schema does not carry and that step 1 already encodes in the GLB.
19. **LOD block roots are spawned `Visibility::Hidden`, carry `NotShadowCaster`, and are revealed with `Visibility::Inherited` when the scene is ready.** Reason: hidden-until-ready is the terrain-patch idiom (`streaming.rs:555`, `:909`) and avoids drawing a half-spawned scene; not casting shadows keeps the sun's cascades exactly as expensive as today (they cover only the full-detail grid, `app.rs:1304-1320`) and stops doubled shadows in the overlap ring.
20. **[new] Add fog only when LOD is enabled.** `DistanceFog` on the streaming camera when `config.lod_enabled`, a linear falloff from roughly the coarsest band's start to the far plane, colour matched to the camera's clear colour. Reason: the engine ships **no fog at all** (grep: zero hits in `crates/engine/src`), so design §6.4's "rely on the existing fog for the residual step" has nothing to rely on; without it the LOD horizon ends in a hard silhouette against the sky. Gated on `lod_enabled`, so no existing scenario's pixels or baselines move.
21. **Far plane: `far = max_band_distance + CELL_SIZE * (max_level * SQRT_2 + stream_radius + 2)` when LOD is on**, computed in `setup_world` (`app.rs:1335`). Reason: band admission is by distance to the block *rectangle*, so a level-16 block admitted at 100 000 measures ~92 681 units across its diagonal — the geometry needs that much room beyond the band. Leave the existing formula untouched when LOD is off.
22. **Config and CLI:** `lod_enabled: bool` (default `false`), `lod_bands: Vec<LodBand>`, `lod_unload_scale: f32` (1.1), `lod_depth_offset: f32` (32.0), `lod_requests_per_frame` (4), `lod_max_in_flight` (8), `lod_commits_per_frame` (4), `lod_fixture: bool`. CLI: `--lod` (accepts an optional following `on|off`), `--no-lod`, `--lod-distances <preset|list>`, `--lod-depth-offset <units>`, `--lod-fixture` (implies `lod_enabled`). Reason: default-off keeps every acceptance number in `scripts/phase2-acceptance.ps1` comparable, as design §6.5 requires; `--lod-fixture` implies the flag so the fixture cannot be run in a contradictory state.
23. **Metrics live in `StreamingMetrics`**, not a new resource: `lod_blocks_resident/loading/failed`, `lod_peak_resident_blocks`, `lod_blocks_covered_skipped` (the design's "culled" — blocks the planner dropped because the full-detail grid covers them), `lod_unloaded_blocks`, `lod_stale_responses`, `lod_asset_failures`, `lod_validation_failures`, `lod_commits`, `lod_max_commit_micros`, `lod_tree_instances` (0 in PR 3), `lod_duplicate_roots/orphaned_roots/missing_roots/out_of_range_roots/misplaced_roots`, `lod_invariant_failures`, `lod_fixture_validated`, `lod_fixture_failures`. Reason: the report already serializes `StreamingMetrics` (`metrics.rs:249`) into `acceptance.json` and the bundle's `streaming.json` (`profiling.rs:117`), and the acceptance runner already reads `report.streaming.*` (`phase2-acceptance.ps1:345`) — a new resource would ripple through `BenchmarkReport`, `write_bundle` and their tests for nothing.
24. **Gates:** extend `no_runtime_failures` (`metrics.rs:336`) with `lod_asset_failures == 0 && lod_validation_failures == 0 && lod_invariant_failures == 0 && lod_fixture_failures == 0` unconditionally (all are 0 when LOD is off, so nothing existing changes), and add them to the `streaming_lifecycle_validated` group at `metrics.rs:176`. Reason: design §6.5 — "zero streaming failures" must keep meaning something once LOD can fail.
25. **`validate_lod_lifecycle` mirrors `validate_streaming_lifecycle`** (duplicate roots per key, orphaned, missing, out-of-range by relaxed band distance) plus one extra: **`lod_misplaced_roots`** — a resident root whose `Transform.translation.x/z` is not `anchor - origin` that frame. Reason: rebasing is the one piece of state LOD shares with the camera and the one that silently corrupts at distance; the invariant makes a rebase bug a counted failure instead of a visual artefact.
26. **Payload bounds are the GLB's model-space aggregate AABB, in the same convention as `statics.bounds_*`/`ExpectedModelBounds` (`components.rs:58-75`).** On readiness, union the spawned primitives' `Mesh::compute_aabb()` (transformed into the root's local space) and compare with the payload bounds; a mismatch beyond 1 unit increments `lod_validation_failures` and hides the block. Reason: identical in spirit to `validate_spawned_transforms_and_bounds` (`streaming.rs:1037`) but aggregate-per-block, not per-primitive, because there can be ~60 resident blocks and validating each primitive's images and samplers the reference way would cost more than the tier.
27. **[new] `--lod-fixture` builds a synthetic LOD tree under the existing fixture directory:** the streaming fixture's temp dir, upgraded to `schema_info = 4` (the literal at `app.rs:229` breaks the moment step 2 bumps `WORLD_DATABASE_SCHEMA_VERSION` — coordinate), plus `lod_grid`, `lod_block` rows for a small patch (level 4: `x,y ∈ {-8,-4,0,4}`; level 8: `{-8,0}`; level 16: `{-16,0}`), plus one tiny GLB per block at `meshes/terrain/<ws>/<ws>.<level>.<x>.<y>.glb` referencing a 1×1 fixture texture, so the recursive-dependency load path is exercised. The GLB is written by a helper in `app.rs` (minimal glTF JSON + BIN chunk: one node, one quad, POSITION/NORMAL/TEXCOORD_0, material without textures plus the fixture texture). Reason: the engine cannot depend on the converter (`crates/engine/Cargo.toml` has no converter dep, and adding one for a fixture is wrong), and a hand-written GLB is ~80 deterministic lines.

## Open risks

1. **Depth precision at a 220 000-unit far plane.** Whether Bevy 0.19's main pass is reverse-Z decides whether a 32-unit offset survives at 20 000 units. Unverifiable from this worktree (the Bevy source is outside it). Measure: `rural` screenshots with `--lod --lod-depth-offset 0|32|64`; if the ordering is lost, the fallback is mechanism (b), a material with `Material::depth_bias`, which is a `lod.rs`-local change.
2. **The LOD surface poking through full-detail terrain in the overlap ring.** The blocks that straddle the full-detail rectangle are drawn and their inner part competes with LAND-derived terrain; 32 units of lowering is not obviously more than the level-4 height error in mountains. Mitigation: raise `--lod-depth-offset`; the structural fix (clipping the block at the ring edge) is out of scope.
3. **The payload's mesh-path spelling and bounds frame are a contract with step 2**, which is being written now. This brief assumes `mesh_path` is the converted runtime path (`meshes/terrain/<ws>/<ws>.<level>.<x>.<y>.glb`, forward slashes; `converted_model_path` is applied anyway and is idempotent) and that `bounds_*` are the GLB's model-space aggregate bounds. Disagreement is a one-line fix in `lod.rs`, but it must be settled before both land.
4. **Schema-4 coordination:** the streaming fixture hard-codes `schema_info = 3` (`app.rs:229`) and will fail the moment step 2 bumps the version. Nothing in this brief fixes it if step 2 lands first without updating it.
5. **HZB and very large blocks.** Bevy culls by mesh AABB; a level-16 block is 65 536 units across, so HZB can never help there and a culling bug would look like holes, not corruption. The `--lod-fixture` visual pass and the `lod_misplaced_roots` invariant are the watch points.
6. **Bevy 0.19 type paths** for `bevy::pbr::NotShadowCaster`, `DistanceFog`, `FogFalloff` and the `SystemSet` derive are asserted from memory and could not be checked against the crate source here; each is a one-line confirmation.
7. **Tree instances are read with the level-4 block** (design §6.2) but PR 3 draws none — the metric will read 0 until PR 4, so it cannot be used as evidence that step 2 populated `lod_tree_instance`.
